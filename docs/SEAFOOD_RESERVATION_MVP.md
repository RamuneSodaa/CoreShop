# Seafood Reservation MVP（卖鱼接龙版）

## 目标

把微信群里的人工接龙改成：鱼货展示 → 顾客选择数量 → 提交预订 → 自动占用库存 → 后台查看订单。

本阶段明确 **不接微信支付**。货款继续由顾客按微信群原方式微信转账，管理员线下确认。

## 已完成

### 1. 预订代替在线支付

- 商品订单创建成功后，不再展示微信支付方式；原支付页改为“预订成功”页。
- 成功页显示订单号、预计金额、线下付款说明，并可进入订单详情。
- 关闭“未在线支付订单自动取消”定时任务，避免已预订鱼货被系统错误释放库存。
- 关闭“催付款”定时任务。
- CoreShop 原有下单库存冻结机制继续保留，因此顾客下单后可销售库存会减少。

### 2. 今日鲜鱼极简首页

- 首页直接读取所有已上架商品，并读取默认货品的实时可售库存。
- 每种鱼显示：图片、鱼名、简介、会员价、非会员参考价、剩余库存和单位。
- 顾客可在首页直接 `- / +` 选择数量，不需要逐个进入商品详情。
- 底部实时汇总已选种类、数量和预计金额。
- 点击“提交预订”后，系统按选择数量写入购物车并进入 CoreShop 现有确认订单流程。
- 多种鱼可以一次预订；确认订单后仍进入“预订成功”页，不唤起微信支付。
- 首页增加“我的预订”、手动刷新库存和下拉刷新。

## 当前约束

- CoreShop 原生购买数量和库存为整数，本阶段按 `1斤 / 2斤 / 3斤`、`1条 / 2条` 使用。
- `CoreCmsProductsServices.GetProductInfo` 返回的 `stock` 已经是 `总库存 - 冻结库存` 后的可售库存，因此前台直接展示该值。
- 会员价使用当前货品 `price`；若 `mktprice` 与售价不同，则首页作为“非会员参考价”显示。正式上线前需按实际价格体系确认后台字段使用方式。
- 当前仍保留 CoreShop 其他商城页面和后台功能，后续会逐步隐藏不需要的支付、优惠券、积分、分销、拼团等入口。
- 当前改动仍在 `seafood-reservation-mvp` 分支和 Draft PR 中，未合并 `master`。

## 下一阶段

1. 把确认订单页进一步改成“确认预订”，隐藏优惠券、积分、发票等无关商城元素。
2. 后台精简为商品 / 库存 / 订单 / 用户四个主要模块。
3. 将订单列表、订单详情里的“待付款 / 去支付”等文案改成“已预订 / 待确认收款”。
4. 增加订单状态：已预订 → 已收款 → 已配货 → 已取货 / 已寄出 → 已取消。
5. 增加 0.5斤、1.5斤等小数斤方案。
6. 做并发库存测试，确保多人同时接龙时不会超卖。
